# «Бесогонка»: защита выбранных заметок

Статус: проект поведения, 2026-09-17. Код приложения не изменён.
Этот вариант заменяет первоначальную идею блокировки всего приложения.

Платформенные детали: [Mac](BIOMETRIC_PANIC_MACOS.md),
[iPhone](BIOMETRIC_PANIC_IOS.md).

## Продуктовое решение

«Бесогонка» — условное название режима для отдельных выбранных пользователем
заметок. Только эти заметки шифруются в рамках новой функции. Обычные заметки
сохраняют существующий способ хранения и открываются без дополнительного входа.

Приложение запускается как обычно. Попытка открыть защищённую заметку показывает
экран «Введите пароль» вместо её содержимого. На этом экране пользователь либо
запускает настоящую разблокировку, либо вводит паник-фразу.

Угроза: человек получил доступ к уже разблокированному устройству, в том числе
под принуждением. Разблокировка ОС сама по себе не должна открывать защищённые
заметки. Скрытый маршрут запуска биометрии не является криптографической защитой
или гарантией сокрытия существования заметок. Принуждение пройти настоящий вход
целиком и полный контроль над работающей ОС остаются за пределами гарантий.

## Вход в защищённую заметку

До явного действия пользователя нет автоматического запроса биометрии, получения
ключа или показа текста. Два ранее обсуждённых варианта сохраняются:

- Клик/тап по достаточно большой, визуально невыделенной области вызывает Touch ID/
  Face ID. В таком варианте поле пароля предназначено для PANIC.
- Альтернатива области: отправка короткой фразы запуска, условно `PROCEED`.
  Пользователь может выбрать 2–3 символа для удобства. Это команда запуска
  биометрии, а не ключ шифрования и не достаточное доказательство авторизации.

Окончательный выбор между областью, фразой или обоими маршрутами ещё не сделан.
`PANIC` и `PROCEED` — названия ролей, а не обязательные встроенные значения.
Настоящая разблокировка здесь по-прежнему означает биометрию с доступом к ключу;
новый самостоятельный вход по текстовому паролю этим документом не вводится.

| Действие | Результат |
| --- | --- |
| Запустить приложение, открыть обычную заметку | Обычный интерфейс без запроса |
| Открыть закрытую защищённую заметку | Экран пароля без текста и без биометрии |
| Нажать скрытую область или отправить фразу запуска | Системный запрос биометрии |
| Успешная биометрия и получение ключа | Открывается защищённая заметка |
| Отмена, ошибка или недоступная биометрия | Защищённая заметка остаётся закрытой |
| Отправить точную паник-фразу | PANIC без биометрии и дополнительного подтверждения |
| Отправить другой текст | Обычная ошибка, никакого удаления |

Проверять полное значение только при отправке, не во время набора, по префиксу или
нечёткому совпадению. Фраза запуска и паник-фраза не могут совпадать. Правила
регистра и пробелов должны быть явными и одинаковыми в обеих оболочках. Ввод не
попадает в логи, историю или persistent frontend state; паник-фраза хранится хешем.

Предлагаемая начальная политика: уход из защищённой заметки закрывает её сессию;
повторное открытие снова запрашивает авторизацию. В пределах открытого редактора
запрос не повторяется. Опциональная общая сессия для нескольких защищённых заметок
или тайм-аут удобнее, но пока не выбраны: разблокировка одной заметки не должна
неявно открывать остальные. Закрытие приложения и блокировка устройства закрывают
защищённую сессию. Политику ухода в фон уточнить по платформам.

## Что защищается помимо редактора

Закрытая заметка не должна раскрывать текст через список, превью, поиск, command
palette, lens, backlinks, историю, логи, уведомления, экспорт или MCP. Предлагается
нейтральная строка «Защищённая заметка» без содержательного имени и сниппета; точный
вид строки ещё не выбран. Скрывать сам факт существования заметки не обещаем.

Нужно защитить название, содержательные метаданные, тело и принадлежащие заметке
вложения/аудио. Открытым может оставаться минимальный технический маркер формата и
непрозрачный ID. Нынешнее шифрование только тела недостаточно для этого обещания.
Общие вложения требуют явного учёта ссылок: PANIC не должен ломать обычные заметки.
Обычные заметки, в которые пользователь сам скопировал защищённый текст, автоматически
секретными не становятся.

Превращение обычной заметки в защищённую — отдельная миграция: убрать открытые
текущие копии, прежний slug/превью/индекс и учесть вложения. Старый plaintext в Git,
бэкапах и экспортах от этого не исчезает. Нельзя обещать задним числом защитить
все существующие копии. Снятие режима требует авторизации и явно создаёт открытые
данные; сам сценарий включения/выключения ещё предстоит спроектировать.

## PANIC: поведение и точная граница

PANIC относится **только к защищённым данным режима «бесогонка» на этом устройстве**.
Он не сбрасывает обычные заметки, весь профиль или приложение.

Не решено, какой набор защищённых заметок стирать:

1. Только заметку, на экране которой введён PANIC.
2. Все заметки режима на этом устройстве.

До реализации этот выбор должен быть сделан явно и отражён в настройке режима.
Ни один вариант не разрешает удалять всю пользовательскую notes root. Ключевая
архитектура должна поддерживать выбранную гранулярность; общий ключ всех заметок
нельзя уничтожать для стирания только одной из них.

Целевой порядок для выбранного набора:

1. Core принимает точную паник-фразу, фиксирует `panic_in_progress` и закрывает
   доступ к целевым заметкам. Повторный PANIC не запускает конкурирующую очистку.
2. Отменяется биометрия и инвалидируются сессии целевых заметок. Поздний успешный
   callback не может вернуть доступ: проверять ID/поколение сессии в core.
3. Останавливаются связанные autosave, OCR, транскрипция, запись, импорт и sync;
   если очередь/репозиторий общие, временно приостановить их целиком до безопасного
   завершения операции. Запретить новым заданиям записывать стираемые данные.
   Сохранения обычных заметок не должны теряться из-за этого.
4. Убираются доступные приложению ключи и открытые копии целевых данных из editor,
   previews, search, caches и временных файлов. При PANIC не выполнять обычный
   flush защищённого черновика после начала стирания. Полное обнуление всех копий
   в JS/ОС/сторонних процессах не обещается.
5. Выполняется выбранный позднее механизм стирания: удаление файлов, уничтожение
   доступа к ключам или сочетание. Он должен работать из закрытого состояния,
   без сети, настоящей биометрии и дополнительного подтверждения.
6. Обычная часть приложения остаётся доступной. Итоговый экран и судьба строки
   защищённой заметки (исчезает или остаётся недоступной) ещё не выбраны.

При ошибке целевые заметки остаются закрытыми; частичный сброс не считается успехом.
Нужен устойчивый к завершению процесса протокол: при следующем запуске продолжить
незавершённый PANIC до доступа к целевым данным и их sync. Не удалять информацию,
необходимую для завершения очистки, раньше времени.

PANIC локальный. Он не стирает Mac с iPhone, iPhone с Mac, Git remote, облачные
сервисы, Photos, бэкапы или экспорты. Обычный pull не должен автоматически вернуть
удалённые защищённые заметки, а push — не должен автоматически разнести аварийное
удаление по другим устройствам. Политика локального исключения/карантина и
согласование её с общим Git-репозиторием — обязательная нерешённая задача.

## Ключи и будущая реализация

Направление: отдельные случайные ключи заметок, платформенное защищённое хранение
ключей или их обёрток, доступ через биометрию. Не выводить ключ из короткой фразы
запуска или паник-фразы. Не передавать ключи через React/JS, localStorage, AsyncStorage
или синхронизируемые настройки. Нативный слой передаёт ключ в Rust.

Биометрия должна разрешать доступ к ключу, а не только переключать флаг интерфейса.
Доступ к данным проверяется на уровне core по конкретной заметке и сессии. Настоящий
MCP/экспорт/worker путь не должен обходить эту проверку. Общий lock всего приложения
не подходит, поскольку обычные заметки должны продолжать работать.

Уничтожение одной записи Keychain не гарантирует уничтожения всех копий ключа.
Нужно учесть обёртки, резервирование, другой телефон и восстановление. Если где-то
остаётся восстановимый ключ, нельзя обещать глобальную нечитаемость копий. Удаление
файлов также не гарантирует очистку SSD, snapshots или Git history. Способ стирания
пока намеренно не выбран.

### Существующее поведение — не использовать как готовую реализацию

`crates/type-core/src/adapters/security.rs` сейчас содержит шифрование тела через
XChaCha20-Poly1305, ключ из пароля через Argon2 и глобальный security runtime.
Названия, frontmatter, записи и вложения этим шифрованием не защищены.

Текущий `panic_reset_local_data` удаляет корни **всех профилей**, пытается удалить
конфигурацию и `native-recordings`, создаёт профиль по умолчанию и три sample notes,
сбрасывает защиту. Некоторые ошибки удаления игнорируются. Этот путь несовместим
с «бесогонкой»: его нельзя вызывать для PANIC отдельной защищённой заметки.
Новая функция требует отдельной модели keys/sessions/scope и согласования с
существующим опциональным глобальным шифрованием; молча отключать его нельзя.

Общий контракт реализуется в Rust application/ports/adapters и экспонируется через
Tauri commands и UniFFI; биометрия и Keychain — платформенные нативные адаптеры.
Спецификацию ключей, sync и безопасную миграцию формата определить до изменений данных.

## Проверка и оставшиеся решения

Проверять на временных хранилищах, не на личных заметках:

- Обычная заметка открывается без запроса, защищённая не раскрывается ни одним путём.
- Область/фраза запускают биометрию; неправильный текст и отмена ничего не стирают.
- Всякое открытие через navigation/deep link/history/MCP/export соблюдает scope.
- PANIC при позднем callback, autosave, sync, OCR, записи, нескольких окнах.
- Обычные заметки и их общие вложения не повреждаются; PANIC одной заметки не
  уничтожает ключи других при выборе поштучного режима.
- PANIC без сети и биометрии, повторно, при ошибке и после прерывания на каждом шаге.
- Sync не возвращает целевые заметки и не распространяет удаление без явной политики.
- Биометрический lockout, смена биометрии, новое устройство и восстановление ключей.

Открытые решения: охват PANIC (одна/все защищённые), метод стирания, ключевая и sync
модель, область/фраза, итоговый экран, политика сессий, onboarding/recovery,
metadata/attachment format и доступность скрытого элемента для клавиатуры/VoiceOver.
