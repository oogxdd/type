# Codex и Claude Code: чтение заметок через MCP

Реализован локальный stdio-сервер `apps/notes-mcp`. Клиент запускает процесс сам;
HTTP-порта и токена нет. Сервер читает только одну явно указанную папку.
Вне подпапки `agent` исходные файлы не меняет; внутри разрешено управление заметками. Node.js >=22.13, зависимости устанавливаются из корня репозитория.

## Что скрывает skip-ai

Назначьте обычный кастомный тег `skip-ai` через существующий интерфейс тегов
редактора. Сервер читает `type_selection_tags` версии 1 и скрывает соответствующие
блоки Tiptap: абзацы, заголовки, блоки кода, абзацы внутри списков.
Регистр имени и пробелы по краям несущественны. Написанное в тексте `#skip-ai`
ничего не скрывает. Другие теги ничего не скрывают.

Сервер использует общий с редактором парсер и алгоритм привязок из
`packages/note-document` и `packages/shared/src/selection-tags.ts`.
Повреждённые/неизвестные метаданные и неразрешённый skip-ai блокируют всю заметку.
Зашифрованные заметки отклоняются: отдельный процесс не получает ключ разблокированного
приложения. Он видит только сохранённую версию файла, поэтому дождитесь автосохранения.

Возвращается полный разрешённый **обычный текст**, с пустой строкой между блоками,
без Markdown-оформления, frontmatter, аннотаций, HTML-атрибутов и адресов ссылок.
Имена файлов тоже не выдаются: автоматический slug мог содержать скрытую мысль.
ID случайные, действуют в рамках процесса; после перезапуска заново вызовите list_notes.

Инструменты чтения всей папки:

- `list_notes({cursor?, limit?})`: ID и очищенные превью.
- `read_note({id})`: `{id, content}` — весь разрешённый текст.
- `search_notes({query, cursor?, limit?})`: буквальный поиск без учёта регистра
  только по очищенному тексту, с превью совпавшей строки.

Для списков следовать `nextCursor` до `null`, даже если страница пуста. При изменении
дерева во время обхода начать заново. `unavailableCount` сообщает число недоступных
заметок среди просмотренных на этой странице, без их имён и содержимого.
Лимит страницы 1–100 (по умолчанию 25), сканирования — 200 заметок за вызов,
размер файла — 1 MiB, глубина — 64, записей дерева — 100 000.

Не выдаются dot-файлы/папки, Recordings, Attachments, _Recordings и не-Markdown-файлы.
Символические и жёсткие ссылки на файлы отклоняются. Сервер проверяет пути повторно
при чтении. Это защита от обычных подмен и выхода за выбранный корень, не полноценная
изоляция от враждебного локального процесса, одновременно меняющего файловую систему.

## Сборка и автоматический тест

Из корня репозитория:

```bash
npm install
npm run mcp:build
npm run mcp:test
```

`dist/main.mjs` собирается с общим кодом workspace; runtime-зависимости остаются
в node_modules. Пересобирайте после изменения редакторского парсера или MCP.
Не переносите один main.mjs без node_modules.

## Подключение Codex CLI

Создайте рабочую папку агента, например `~/notes-agent`. Это удобство, а не защита
файловой системы. Запуск из папки заметок тоже возможен, но сам клиент может читать
файлы инструкций при загрузке контекста. Не помещайте приватные заметки в AGENTS.md.

Добавьте сервер в `~/.codex/config.toml` (замените путь заметок и при необходимости
путь репозитория). Пример не меняет настройки автоматически:

```toml
[mcp_servers.notes]
command = "node"
args = ["/Volumes/KINGSTON/Projects/type/app/apps/notes-mcp/dist/main.mjs", "--notes-root", "/ABSOLUTE/PATH/TO/NOTES"]
enabled_tools = ["list_notes", "read_note", "search_notes", "list_agent_folder", "read_agent_note", "create_note", "create_folder", "update_note", "move_note", "move_folder", "delete_note", "delete_folder"]
```

Запуск для этой сессии:

```bash
cd ~/notes-agent
codex -c features.shell_tool=false -c 'web_search="disabled"' --sandbox read-only
```

`features.shell_tool=false` отключает стандартный терминал (`cat`, `rg`, Python и
прочие команды через этот инструмент). `enabled_tools` ограничивает только данный
MCP. `read-only` запрещает запись в рамках sandbox, но НЕ запрещает чтение оригиналов.
Отключите другие MCP/плагины и инструменты, предоставляющие чтение файлов или выполнение
кода. Проверьте активные инструменты и подключение через `/mcp`; конфигурация выше
не является глобальным режимом «только инструменты этого MCP».

Правила команд `.rules` не заменяют такую настройку: запрет одного `cat` не закрывает
другие способы чтения. Никогда не используйте bypass/full-access для этого сценария.
Конкретная установленная версия Codex должна поддерживать указанные настройки.

## Подключение Claude Code

В `~/notes-agent/mcp.json`:

```json
{
  "mcpServers": {
    "notes": {
      "command": "node",
      "args": ["/Volumes/KINGSTON/Projects/type/app/apps/notes-mcp/dist/main.mjs", "--notes-root", "/ABSOLUTE/PATH/TO/NOTES"]
    }
  }
}
```

```bash
cd ~/notes-agent
claude --tools "" --strict-mcp-config --mcp-config ./mcp.json \
  --allowedTools "mcp__notes__*"
```

`--tools ""` отключает встроенные инструменты, `--strict-mcp-config` ограничивает
MCP-конфигурацию указанным файлом. `--allowedTools` разрешает вызовы без вопросов,
но сам по себе НЕ запрещает другие инструменты. Не подключайте другие плагины,
хуки или автоматизации, имеющие доступ к оригиналам. Не используйте bypassPermissions.

## Ручная проверка

1. Выберите отдельную тестовую рабочую папку в Type Dev. Создайте заметку из трёх
   абзацев: `Открытая мысль`, `PRIVATE_CANARY_9482`, `Ещё одна открытая мысль`.
2. Через существующий интерфейс назначьте среднему абзацу кастомный тег `skip-ai`.
   Дождитесь сохранения. Укажите именно эту тестовую папку в MCP-конфигурации.
3. Подключитесь новым сеансом агента. Попросите: «Через notes.list_notes найди
   заметку, затем read_note и покажи весь полученный текст». Должны остаться два
   открытых абзаца. Убедитесь по результату инструмента, а не только пересказу модели.
4. Попросите вызвать `search_notes` с `PRIVATE_CANARY_9482`. Совпадений быть не должно.
   Эта строка тестовая: вы сами отправите её модели в запросе, поэтому проверяется
   отсутствие в результате инструмента, а не незнание моделью строки из запроса.
5. Вставьте абзац выше скрытого в редакторе, сохраните и повторите чтение. Скрытый
   абзац должен остаться скрытым. Снимите тег, сохраните — текст снова доступен.
6. В копии тестового файла измените помеченный текст внешним редактором без обновления
   метаданных. `read_note` по ранее выданному ID должен вернуть ошибку восстановления
   skip-ai; список пропустит эту заметку и увеличит unavailableCount.

Автотесты выполняют MCP initialize/list/call через SDK, проверяют скрытие, внешние
изменения, повторы текста, превью, поиск, ссылки на файлы и отсутствие записи вне agent.
Для проверки именно stdio без модели: `node scripts/test-notes-mcp.mjs` после сборки.
Этот тест создаёт временные файлы и удаляет их, не читая личные заметки.

## Граница защиты и мобильное приложение

Отключение инструмента терминала ограничивает модель, но не меняет права самого
процесса Codex/Claude в ОС. MCP также не может запретить другим инструментам читать
оригиналы. Для строгой изоляции агенту нужно отдельное окружение без папки оригиналов;
этот stdio-вариант сам такую изоляцию не создаёт. Для контейнера без оригиналов
потребуется отдельный доступный снаружи транспорт к доверенному серверу, например
аутентифицированный HTTP; HTTP в этой версии не реализован.

Мобильный редактор пока не адаптирован к обновлению block-привязок. Теги синхронизируются
в Markdown, но правка помеченного текста на телефоне может сделать привязку
неразрешённой; MCP тогда отклонит заметку. До адаптации перепроверяйте такие назначения
на компьютере. Уже отправленный агенту текст не исчезает из истории после назначения
skip-ai. Закрытие приложения не останавливает отдельный stdio-процесс.

План перехода на строки и мобильной адаптации: [LINE_TAG_MIGRATION.md](LINE_TAG_MIGRATION.md).
Точка замены алгоритма — `apps/notes-mcp/src/projection.ts`. Контракт MCP и проверки
фильтрации должны оставаться неизменными.

## Запись только в root/agent

Сервер создаёт папку `agent` при первой операции записи. Регистр имени — строчный.
Все пути следующих инструментов относительны этой папке: `ideas/plan.md` означает
`<notes-root>/agent/ideas/plan.md`, а не `<notes-root>/ideas/plan.md`.

- `list_agent_folder({path?: "ideas"})`: содержимое папки; пустой path — корень agent.
- `read_agent_note({path})`: очищенный текст и `revision` текущего файла.
- `create_note({path, content})`: новый `.md`, создаёт родителей, отказывается перезаписывать.
- `create_folder({path})`: создаёт подпапку и родителей.
- `update_note({path, content, expectedRevision})`: полная замена файла, включая frontmatter
  и теги, только при совпадении revision из чтения. Это не патч очищенного текста.
- `move_note({source, destination})`, `move_folder({source, destination})`: перенос/переименование
  только внутри agent, без перезаписи назначения.
- `delete_note({path})`: окончательное удаление.
- `delete_folder({path, recursive?: false})`: по умолчанию только пустой папки;
  `recursive: true` удаляет её заметки и вложенные папки. Сам корень agent не удаляется.

Чтение внутри agent также фильтрует skip-ai. Названия файлов и подпапок внутри agent
доступны через list_agent_folder: это выделенная область агента. Не размещайте там
личные оригиналы, которые агенту запрещено переименовывать или удалять.

Все пути проверяются сервером: абсолютные пути, `..`, dot-entries, обратные слеши,
симлинки и жёсткие ссылки отклоняются. Файловые операции поддерживают Markdown;
папка с посторонними файлами/ссылками не удаляется рекурсивно. Лимит рекурсивной
операции — 10 000 записей. Операции этого процесса сериализованы; файловая проверка
не заменяет OS sandbox против враждебных параллельных изменений другим процессом.

`--sandbox read-only` у Codex не запрещает серверу MCP писать в agent: MCP — отдельный
процесс с собственной проверкой прав. Для режима MCP только для чтения оставьте
в enabled_tools лишь list_notes/read_note/search_notes. Чтобы новые методы появились,
пересоберите сервер, обновите прежний enabled_tools и перезапустите сеанс агента.
Клиент может запрашивать подтверждение мутаций: инструменты корректно помечены как
изменяющие данные, удаления — как разрушительные.

Тест записи: попросите создать `ideas/test.md`, прочитать его, заменить текст с
полученным revision, перенести в `done/test.md`, затем удалить. Попытка создать
`../Feed/test.md` должна вернуть ошибку. Делайте эту проверку на тестовой папке.
Изменения сохраняются на диск; если открытое приложение не обновило список сразу,
обновите дерево/переоткройте рабочую папку.
