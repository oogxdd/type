# iPhone: режим «бесогонка»

Статус: проект, 2026-09-17; не реализовано.
[Общий контракт и PANIC](BIOMETRIC_PANIC_UNLOCK.md).

## Пользовательский сценарий

Приложение запускается как обычно: Capture и обычные заметки не требуют нового
входа. Попытка открыть защищённую заметку показывает «Введите пароль» вместо её
текста. Возврат к обычным заметкам остаётся доступным.

Тап по визуально невыделенной области или отправка короткой фразы запуска вызывает
Face ID либо Touch ID — в зависимости от модели iPhone. До этого биометрия не
запускается, даже если владелец смотрит на экран. Успешное получение ключа открывает
сессию этой заметки; отмена/ошибка оставляют её закрытой.

Паник-фраза запускает PANIC только для защищённого набора, без биометрии и
дополнительного подтверждения. Охват «одна/все защищённые» ещё не выбран. Обычные
заметки, весь профиль и обычные вложения не удаляются.

Область должна быть удобной для пальца при открытой клавиатуре, разных safe areas,
ориентации и масштабе текста; без выделяющей её иконки, подписи или заливки.
VoiceOver/альтернативный ввод нужно спроектировать отдельно. Обнаружение этой
области не должно обходить реальную защиту ключа.

Поле защищённого ввода: без автокоррекции, автокапитализации, подсказок и сохранения
строки. Проверять полное значение по отправке, не по первым символам во время набора.

## Keychain и нативный мост

React Native управляет экраном. Нативный адаптер Keychain/LocalAuthentication
передаёт ключ в Rust напрямую; JS получает результат авторизации, не ключ.
Expo Go/mock core не подтверждают безопасность: нужна нативная сборка на iPhone.

Предлагается исследовать несинхронизируемые Keychain items с
`kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly` и ACL `biometryCurrentSet`.
Этот класс требует код-пароль устройства и не предназначен для переноса ключей
на другое устройство. Изменение набора биометрии может инвалидировать доступ:
до включения режима определить recovery или явное принятие потери доступа.
Окончательный набор флагов и гранулярность ключей зависят от охвата PANIC.

Код-пароль iPhone не является fallback для открытия заметки; широкий `userPresence`
не равнозначен «только биометрия». Если ОС требует код-пароль для восстановления
работоспособности биометрии, его ввод сам по себе не открывает заметку: нужен
новый явный запуск и успешная биометрическая проверка.

Для Face ID требуется `NSFaceIDUsageDescription` и разрешение пользователя.
Отказ, lockout или неработающий сенсор оставляют защищённую заметку закрытой,
без бесконечных автоматических повторов. Обычная часть приложения работает.

## Фон, PANIC и прерывание

Перед снимком переключателя приложений скрывать защищённый текст нейтральным
покрытием. Предлагается закрывать его сессию при уходе из заметки, в фон и при
блокировке устройства. Переход в `inactive` из-за собственного Face ID/Touch ID
dialog не должен ломать вход; отличать его от реального ухода в фон.

PANIC следует общему протоколу core. Отменить биометрию и игнорировать запоздалый
успех. Остановить связанные запись, аудиосессию, Live Activity, временные файлы,
OCR и sync; обычные данные при этом сохранить. Удаление выбранного Keychain item
без биометрии проверить до выбора этого механизма стирания.

iOS может приостановить/завершить приложение посреди очистки. Не обещать, что она
завершится в фоне: при следующем запуске возобновить PANIC до доступа к целевым
заметкам и их синхронизации. Capture/deep links/share/import не обходят защиту.

Локальный PANIC не удаляет копии на Mac, в Photos, Git remote, бэкапах, экспортах
или внешних сервисах. Автоматическое восстановление целевых заметок через sync
запрещено; способ сочетать это с обычной синхронизацией ещё нужно спроектировать.

## Проверки на настоящем iPhone

- Обычные заметки не требуют биометрии и переживают PANIC защищённых без изменений.
- Face ID и Touch ID: одинаковые переходы, различающийся системный интерфейс.
- Нет запроса до явного действия; отмена/отказ не раскрывают текст.
- Открытие через список, поиск, историю и deep link соблюдает per-note scope.
- Переключатель приложений, блокировка телефона, поздние callbacks не раскрывают текст.
- PANIC без сети, во время sync/recording и с завершением процесса на каждом этапе.
- Смена биометрии, снятие код-пароля, backup restore и новый iPhone соответствуют
  выбранной политике восстановления и не дают молчаливого обхода защиты.
