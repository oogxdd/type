It works great with your existing DMG workflow: you build → publish an update (e.g. to GitHub Releases) → the installed app (from the DMG) automatically detects, downloads, and installs the update without you having to reinstall a new DMG every time.
This mirrors your mobile/TestFlight flow perfectly. The updater uses the .app.tar.gz bundle (not the DMG) on macOS, so once the user has the app installed from DMG, future updates just replace the app bundle in place.
Quick Setup (Tauri v2 – this is the current version)

Install the updater plugin
In your project root:Bashnpm install @tauri-apps/plugin-updater(Also recommended: npm install @tauri-apps/plugin-dialog so you can show nice update prompts.)In src-tauri/Cargo.toml (or via cargo add):tomltauri-plugin-updater = "2"
tauri-plugin-dialog = "2"Register it in src-tauri/src/lib.rs (or main.rs):Rusttauri::Builder::default()
    .plugin(tauri_plugin_updater::init())
    .plugin(tauri_plugin_dialog::init())
    // ...
    .run(tauri::generate_context!())
Generate updater signing keys (required for security)
Run once:Bashnpx tauri signer generate -- -w ~/.tauri/your-app.keyThis creates:
~/.tauri/your-app.key (private key – keep it secret, never commit it)
~/.tauri/your-app.key.pub (public key)
Add the public key content (not the file path) to src-tauri/tauri.conf.json later.
Configure the updater in tauri.conf.jsonJSON{
  "tauri": {
    "updater": {
      "active": true,
      "pubkey": "YOUR_PUBLIC_KEY_HERE",   // paste the whole key string from .pub file
      "endpoints": [
        "https://github.com/YOUR_USERNAME/YOUR_REPO/releases/latest/download/latest.json"
      ],
      "createUpdaterArtifacts": true
    }
  }
}
Add permissions (in src-tauri/capabilities/default.json or your capability file):JSON{
  "permissions": [
    "updater:allow-check",
    "updater:allow-download-and-install"
  ]
}
Check for updates from your frontend (JS/TS)
Create a simple updater function (e.g. call it on app start):TypeScriptimport { check } from '@tauri-apps/plugin-updater';
import { ask } from '@tauri-apps/plugin-dialog';
import { relaunch } from '@tauri-apps/plugin-process';

async function checkForUpdates() {
  const update = await check();
  if (!update?.available) return;

  const yes = await ask(
    `Update to ${update.version} is available!\n\nRelease notes:\n${update.body || 'No notes'}`,
    { title: 'Update Available', kind: 'info', okLabel: 'Update Now' }
  );

  if (yes) {
    await update.downloadAndInstall();
    await relaunch();        // restarts the app with the new version
  }
}

// Call this early, e.g. in your main component
// onMount(() => { checkForUpdates(); });

Publishing Updates (your new "TestFlight" flow)
Recommended & simplest way: GitHub Releases + tauri-action
Use the official tauri-action in GitHub Actions. It:

Builds your app (including .app.tar.gz + .sig)
Creates a latest.json automatically
Uploads everything to a new GitHub release

Then just bump the version in tauri.conf.json (or package.json), push a tag or merge to a release branch, and you're done. The endpoint you added earlier (.../releases/latest/download/latest.json) will point to it automatically.
You can also do it manually (create release + upload the macOS artifacts + latest.json), but the action is way cleaner and identical to your mobile build process.
Important macOS Notes

The DMG is only for the initial install. Updates use the .app.tar.gz (Tauri generates it automatically when createUpdaterArtifacts: true).
Your app must be code-signed and notarized for the updater to work smoothly (you probably already do this for DMG builds).
The updater will replace the .app bundle in /Applications (or wherever the user installed it).

Once set up, you just:

Build (tauri build)
Publish release (GitHub)
Your production app (the one you use daily) will see the update on next launch or when you call check().

This is the standard way most Tauri apps do it (very similar to Electron/Sparkle on macOS).
If you hit any snags (e.g. signing, GitHub private repo, custom server, etc.), just paste the error or your current tauri.conf.json and I’ll help debug it step-by-step. You’ve already got the mobile side sorted — desktop updater is the missing piece and it’s actually pretty smooth once the keys + config are in place. 🚀
